# wiki-translate Skill

This skill helps a human editor prepare a translated Wikipedia draft. **It does not publish to Wikipedia.** The draft must be reviewed by a human fluent in both languages before any publication; see the `review-notes.md` it produces.

## When to use

Invoke this skill when the user asks for help translating a Wikipedia article between languages — for example:

- "Translate https://en.wikipedia.org/wiki/Brett_Whiteley into Chinese"
- "把這個中文維基條目幫我翻成英文：https://zh.wikipedia.org/wiki/九子奪嫡"

Currently supports English ↔ Chinese well; other language pairs work but are less tested.

## Prerequisites

The `wiki-translate` CLI must be installed:

```bash
pip install -e .   # if running from the repo
# or
pip install wiki-translate
```

## Workflow

### 1. Prepare (CLI fetches source article, emits prompts)

```bash
wiki-translate prepare <wikipedia-url> --target <lang> --out ./wt-work
```

This:
- Fetches the source article's wikitext, sections, langlinks, and revision id
- Writes one prompt file per section to `./wt-work/prompts/<section-id>.prompt.txt`
- Writes `./wt-work/job.json` (manifest used by finalize)
- Writes `./wt-work/AGENT_README.md` with detailed instructions for you

### 2. Translate each section yourself

For each file in `./wt-work/prompts/`:

1. Read the file. It contains the source text and explicit instructions about preserving wiki markup, citations, and not adding information.
2. Follow those instructions precisely. Pay particular attention to:
   - Preserving `[[links]]`, `{{templates}}`, `<ref>...</ref>` exactly
   - Keeping any term you're uncertain about in parentheses after the translation
   - Adding translator notes (after `---TRANSLATOR-NOTES---`) if you made non-trivial decisions
3. Write your translation to `./wt-work/translations/<same-section-id>.txt`.

A prompt at `./wt-work/prompts/001-lead.prompt.txt` produces a translation at `./wt-work/translations/001-lead.txt`.

### 3. Finalize (CLI assembles final draft + attribution)

```bash
wiki-translate finalize ./wt-work --out ./output
```

This produces in `./output/<article-title>/`:

- `<title>.wikitext` — translated draft with DRAFT banner and `{{LLM-assisted translation|reviewed=no}}` template
- `edit-summary.txt` — CC BY-SA-compliant edit summary (use this when publishing)
- `talk-template.txt` — `{{Translated page}}` template for the article talk page
- `review-notes.md` — items the human reviewer must check (citation count mismatches, hallucination hints, your translator notes)

### 4. Hand off to the user

Tell the user:

- Where the files are
- That `review-notes.md` must be opened before doing anything else
- That Wikipedia policy requires the publishing editor to be fluent in both languages and to verify all citations
- That the tool does **not** publish to Wikipedia — the user must do that manually after review

## Do NOT

- Do NOT call any Wikipedia edit API or attempt to publish on the user's behalf.
- Do NOT remove the DRAFT banner or the `{{LLM-assisted translation}}` template.
- Do NOT modify or weaken the review-notes.md generated by the finalize step.
- Do NOT translate political-sensitive topics as "demos" or "examples" if the user hasn't specifically requested them.

## If the target language already has an article

The CLI detects this via langlinks and notes it in `AGENT_README.md` and `review-notes.md`. In MVP, this skill only translates the source — it does not merge with the existing target article. Tell the user they must manually compare and integrate (not overwrite) the existing version. Future versions will support automated comparison and merging.
